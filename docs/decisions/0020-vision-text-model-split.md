# ADR-0020: 抽出モデルを vision / text で分離し、日付誤りの検証を追加（0018 の適用範囲を text に限定）

- Status: Accepted
- Date: 2026-07-26

## Context

ADR-0018（2026-07-21）は ST/prod の `GEMINI_MODEL` を `gemini-flash-lite-latest` に変更した。判断根拠は **text 抽出パスの実測**（大阪ステーションシネマの週間ページ・T・ジョイ梅田）で、`gemini-flash-latest` が無料枠の容量逼迫で 503／応答保留になり全取込が失敗していたためである。この変更は `LLM_PROVIDER`/`GEMINI_MODEL` を **text/vision で共有**していたため、vision パスにも自動的に適用された。

**vision 劇場はシネ・ヌーヴォ1館のみで、ADR-0018 の際に vision パスでの再検証を行っていなかった。**

2026-07-26 の P1-6 Step B（実 Cron 検証）で、flash-lite による初めてのシネ・ヌーヴォ取込が走り、以下が判明した。

- シネ・ヌーヴォの `schedule_url` の画像は **7/25〜8/28 の月間グリッド**（横軸=日付の列、縦軸=2スクリーン）である。
- 抽出結果は **22件で、すべて `date=2026-08-01`**。R2 スナップショットの画像と突合すると、シネ・ヌーヴォX 列に載っている**全日程の上映が単一日に潰れて**いた。同一スクリーンで 01:30 に3作品が同時開始し、01:10〜02:35 と 01:20〜03:00 が重複するなど物理的に不可能な内容だった。
- 過去の成功 run（`gemini-flash-latest`）は 2026-07-12 が 145件、07-15 が 136件で、いずれも日付が正しく分散していた。**モデル以外の条件（プロンプト `vision_v1`・前処理・画像形式）は変わっていない。**

さらに2つの問題が重なり、誤った結果が D1 に書き込まれた。

1. **V2 `COUNT_ANOMALY` が発火しなかった**。`recentAvgCount()` は成功 run が3件未満のとき `undefined` を返し V2 を丸ごとスキップする実装で、シネ・ヌーヴォの成功 run は2件（145/136）しか無かった。2件でも平均を取れば 140.5 で、22件は 50% 下限（70.25）を大きく割るため検出できたはずだった。
2. **洗い替えが被害を拡大した**。`replaceScreeningsByDate()` は `coverageFloor`（取込当日=7/26）から抽出最大日（8/1）までを `enumerateDates` で列挙し、その全日を DELETE してから抽出分を INSERT する。抽出が 8/1 しか返さなかったため **7/26〜7/31 の6日分（各日4件）が削除され、22件の誤データだけが残った**。

実害として `/plan` は 2026-08-01 に対し「シネ・ヌーヴォで5本はしご」という**一見もっともらしいが事実と異なる**プランを返す状態になった（実際にはそれらの作品は別々の日に上映される）。欠損よりも自信を持って誤る方が危険である。

## Decision

1. **抽出モデルを modality（vision / text）ごとに指定できるようにする。**
   - `GEMINI_MODEL_VISION`（新規 var）: vision 抽出のモデル。**既定 `gemini-flash-latest`**。
   - `GEMINI_MODEL`: text 抽出のモデル。ST/prod は ADR-0018 のとおり `gemini-flash-lite-latest` を維持。
   - `createLlmClient(env, modality)` に modality を明示的に渡す（`ExtractInput.images` の有無から推測しない。モデル選択を付随的なプロパティに結び付けないため）。
   - **ADR-0018 の適用範囲を text 抽出に限定する**と読み替える。0018 の「戻す場合は var を削除」も text に限った記述とする。
2. **V7 `SCREEN_TIME_OVERLAP` を追加する**（`validateNormalized`＝正規化後・書込前）。同一 `(businessDate, screenName)` で上映時間帯が重複、または開始時刻が完全一致する別作品を NG とする。詳細な誤検知回避条件は `docs/06` §5。
3. **V2 の履歴下限を 3 件 → 2 件に下げる**（`recentAvgCount`）。
4. **失われた 7/26〜7/31 は R2 再抽出で復旧する**。スナップショット（`raw/thr_cnv01/2026-07-26/2026-07-26T08:01:59.961Z_*.gif`）に月間グリッド全体が含まれており、**先方サイトへの再取得は不要**（ハードルール4に適合）。

## Consequences

- vision と text で別モデルを使うため、`ingest_runs.llm_model` に2種類の値が混在する。コスト集計（`docs/06` §8）は劇場単位で見れば区別できる。
- `gemini-flash-latest` は ADR-0018 時点で無料枠の容量逼迫があった。vision パスは **1劇場・1日1回・小さな画像1〜2枚**で text より要求が軽いが、503 が再発する可能性は残る。再発した場合は `extraction_failed` として記録・通知され、R2 再抽出で何度でも再試行できる（先方アクセスなし）。恒久的に使えなくなった場合は vision 用の代替モデルを別 ADR で決める。
- V7 は二本立てを1つの開始時刻で併記するサイトで誤検知しうる。その場合はレビューキューでの承認で通す（データ損失より軽い扱い）。
- V2 の下限を下げたことで、新規劇場のランプアップ期（単日→複数日への移行など）に COUNT_ANOMALY が出やすくなる。これは意図した人間確認であり、承認すれば平均が追従する。
- **モデルやプロンプトを変更する際は、text と vision の両パスで実データ検証を行う**という運用上の教訓を得た。今回は「1劇場しかないパス」の検証が漏れた。

## Alternatives considered

- **`ExtractInput.images` の有無からモデルを推測する**: 呼出側の変更が不要で最小だが、モデル選択が付随的なプロパティに依存する。将来 text 呼出に画像を添えるなどの変更で静かに壊れる。**不採用**（modality を明示的に渡す）。
- **vision も flash-lite のままでプロンプトを改良する**（`vision_v1` → `vision_v2` で日付列の読み取りを強化）: 版管理規則に沿う正攻法だが、同一プロンプト・同一画像で flash-latest は 136件を正しく取れているため、**モデル能力が律速であることが実証済み**。プロンプト改良で埋まる保証がなく、検証コストも高い。**不採用**（将来 flash-latest が使えなくなった場合の選択肢として残す）。
- **全体を `gemini-flash-latest` に戻す**: text パスが ADR-0018 の 503／出力律速に戻り、4館の取込が全て止まる。**不採用**。
- **洗い替え範囲に「抽出がカバーしない日は削除しない」ガードを入れる**: 今回のデータ損失を直接防げるが、休館日（その日は 0 件が正しい）と「抽出漏れ」を区別できず、閉館日のデータが永久に残る副作用がある。V7 が書込**前**に走って run 自体を止めるため、この class の事故はそれで防げる。**不採用**（必要になれば別 ADR）。
- **V2 の履歴下限を 1 件にする**: 1件では劇場のブレ（週替わり編成）で誤検知が多くなる。**不採用**（2件を下限とする）。
