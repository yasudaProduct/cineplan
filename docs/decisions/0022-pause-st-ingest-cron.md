# ADR-0022: ST の取込ディスパッチ Cron を一時停止（0021 の一部更新）
- Status: Accepted
- Date: 2026-09-01

## Context

ADR-0021 で ST の Cron を3本（取込ディスパッチ・TravelMatrix週次・保持削除）有効化し、ST を個人利用の常用環境として運用している。

Cron の発火自体は正常に動作している一方、`#cineplan-alerts`（Slack）の記録では 2026-08-19 頃から今日まで、ほぼ毎日複数劇場で Gemini 無料枠のクォータ超過（429 `generate_content_free_tier_input_token_count` 上限到達）・高負荷（503）による取込失敗（`extraction_failed`）が発生していることが判明した。原因（無料枠の想定不足か、リトライ実装が消費を増やしているか等）の調査は別途着手している。

原因が判明し対策するまでの間、先方サイトへの自動アクセスと失敗の繰り返しを止めるため、取込ディスパッチのみを一時停止する。

## Decision

`packages/ingest/wrangler.toml` の `[env.st.triggers]` から取込ディスパッチ用の `"0 20 * * *"` を除外する。TravelMatrix 週次（`0 18 * * 1`）と保持削除（`0 17 * * *`）は ADR-0021 のまま継続する。

管理サイトからの手動取込（1日1回の上限は変わらず）は影響を受けない。

## Consequences

- ST の上映データは本停止中、新規取込が行われず鮮度が徐々に落ちる（N-02 は取込 Cron の稼働が前提のため、停止中は満たされない）。`/plan` は最後に取り込まれたデータで動き続ける。
- TravelMatrix・データ保持は影響を受けず引き続き稼働する。
- 再開する際は `crons` 配列に `"0 20 * * *"` を戻し、`develop` へ push して再デプロイする。再開の判断基準は特に定めていないため、次にこの決定を覆すときは理由とともに新しい ADR を追加する。

## Alternatives considered

- **劇場を個別に `paused` にして負荷を減らす**: Cron 自体は動き続けるため、原因調査中に他の劇場でも同種の失敗が起き続ける。全体を止める方が調査中のノイズが少ない。不採用。
- **モデルやリトライ回数を先に変更して Cron は維持する**: 原因（クォータ設定か実装か）が未確定な状態でコード変更を重ねると切り分けが難しくなる。まず自動アクセスを止めて調査を優先する。不採用。
