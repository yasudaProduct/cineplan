# ADR-0007: 取込サービスを公開サービスから分離する
- Status: Accepted
- Date: 2026-07-07

## Context
取込（スクレイピング・LLM 抽出）は壊れやすく、失敗が利用者向けサービスに波及すると可用性が下がる。管理・スケール要件も公開 API と異なる。

## Decision
取込サービス（+ 管理サイト）を独立した Worker パッケージとし、公開サービスとは D1 の Screening データ経由でのみ疎結合にする。

## Consequences
- 取込が落ちても公開サービスは最後に成功したデータで応答継続できる（N-03）。
- デプロイ・スケール・権限（Access）を独立管理できる。
- 結合点が D1 スキーマに集約されるため、スキーマ変更の影響範囲が明確。

## Alternatives considered
- 単一 Worker に全機能同居: 初期は単純だが、障害分離・権限分離ができず、取込の重処理が API のレイテンシに影響しうる。
