# ADR-0021: ST を個人利用の常用環境とし、prod 構築を一般公開時まで保留（0010 の運用変更）
- Status: Accepted
- Date: 2026-08-14

## Context

P5-6 まで完了し、ロードマップに残るのは P5-7（本番昇格）のみ。しかし prod 昇格には独自ドメイン取得・prod リソース一式（D1/R2/KV/Queues）・prod シークレット・法務文面の確定・タグ承認（`docs/guides/01` §5）が必要で、いずれもオーナー作業であり費用も発生する。

一方、現時点の利用者はオーナー本人のみで、一般公開の予定は当面ない。ST は P4-0 以降 5館の実データ取込・`/plan`・共有ページ・管理サイトまで一通り動作しており、個人利用に必要な機能は既に揃っている。

この状況で prod を構築しても、ST とほぼ同じものを二重に管理することになる。他方 ST は「開発中に先方サイトを毎日叩かない」という理由で Cron が原則 OFF（`docs/spec/11` §3.2）であり、そのままでは日々のデータ更新が行われず常用できない。

## Decision

1. **prod 環境の構築（P5-7）を一般公開の意思決定時まで保留する。** `wrangler.toml` の `[env.prod]` 定義・`deploy-prod.yml`・`docs/guides/01` §5 の手順は**削除せずそのまま残す**（再開時にそのまま使う）。
2. **ST を個人利用の常用環境と位置づける。** 開発は local → ST の2段運用とし、`develop` push による ST 自動デプロイ（ADR-0016）は維持する。
3. **ST の Cron を有効化する**（prod と同じ3本）。
   - 取込ディスパッチ: `0 20 * * *`（20:00 UTC = 05:00 JST）。P1-6 Step C の実測（5館サイクル340秒）に基づき、N-02（対象日の前日 06:00 JST までに取込完了）に余裕を持たせるため prod 想定の 21:00 UTC より1時間前倒しする。
   - TravelMatrix 週次: `0 18 * * 1` / データ保持削除: `0 17 * * *`。この2つは `scheduled()` が**文字列の完全一致**で分岐するため（`packages/ingest/src/index.ts` の `MATRIX_CRON`/`RETENTION_CRON`）prod と同一文字列を使う。取込ディスパッチは分岐の else 節（フォールバック）なので文字列が異なっても正しく動作する。
4. **User-Agent の連絡先 URL を ST の実 URL に差し替える**（`https://cinema-web-st.yuta-develop-ct.workers.dev/bot`）。従来のプレースホルダ `https://example.com/bot` は到達不能で `docs/spec/08` §3 の「連絡先を含める」を満たしていなかった。UA 文字列は3箇所（`packages/ingest/src/worker/fetch.ts` / `packages/api/src/lib/station-geo.ts` / `packages/web/app/lib/site.ts`）に重複しているため同一値に保つ。

## Consequences

- **ST が「1劇場1日1セッション」を担う唯一の環境になる。** prod と ST の両方で Cron が回ることはないため `docs/spec/08` §0・§3 と整合する。**将来 prod を構築する際は、ST の取込 Cron を停止してから prod の Cron を有効化する**（両方が同時に回ると同一劇場へ1日2セッションとなりポリシー違反になる）。この順序は `docs/guides/01` §5 に明記する。
- 開発デプロイ（`develop` push）が常用環境をそのまま更新する。個人利用のため許容するが、壊れた変更を `develop` に入れると翌朝の取込が失敗しうる。CI（typecheck/lint/test）がその防波堤である点は従来どおり。
- ST の web は workers.dev URL で誰でも到達できる（アクセス制限なし）。積極的に公開・宣伝はしないが、URL を知られれば閲覧可能である点は変わらない。`/admin` は Cloudflare Access 配下（P4-1）で保護済み。
- UA が到達可能な URL を指すようになり `docs/spec/08` §3 の「正直に名乗る・連絡先を含める」を満たす。一方 `/bot` の**停止依頼メールアドレスは未設定（「準備中」表示）のままとする**（オーナー判断）。劇場側から停止依頼を受ける手段が実質無い状態を当面受け入れるリスクを認識したうえでの選択であり、**一般公開時までに `CONTACT_EMAIL` を設定する**。
- P1-6 で「ST では検証できない（cron 文字列の完全一致で選ばれるため one-shot 式では通らない）」として prod 初回月曜のログ確認に先送りしていた **TravelMatrix cron 分岐が、ST で実文字列により実行されるようになる**。初回月曜のログで確認できる。
- 独自ドメイン・法務文面の最終確認・prod シークレットといったオーナー作業は、一般公開の意思決定まで発生しない。

## Alternatives considered

- **予定どおり prod を構築して個人利用する**: 環境が完全分離され本来の設計どおりだが、ドメイン取得費用・prod リソース・シークレットの二重管理が個人利用には過大。一般公開の意思決定前にコストを先払いする必要がない。不採用。
- **ST の Cron を OFF のままにして毎日手動取込する**: 先方サイトへのアクセスは最小になるが、使いたい日の前日に手動操作が必要で常用に耐えない。また手動取込も1日1セッション制限の対象であり、自動化しても先方への総アクセス量は変わらない（むしろ操作忘れによる再実行のほうが読めない）。不採用。
- **ST とは別に「personal」環境を新設する**: 環境が3→4に増え wrangler/Actions/シークレットの管理が複雑化する。ST には既に実データ5館分が入っており、作り直す利点がない。不採用。
