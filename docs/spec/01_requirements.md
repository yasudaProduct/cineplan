# 要件定義書 — 映画館はしごスケジューリングサービス

- Version: 0.1
- Status: Draft
- 関連: `02_glossary.md` / `05_routing-algorithm.md` / `08_compliance-policy.md`

## 1. サービス概要

複数の映画館の上映スケジュールをもとに、1日で効率よく映画を「はしご鑑賞」するためのルート（観る作品・順序・移動を含むタイムライン）を提案するサービス。

- 上映スケジュールは各映画館の公式サイトから取得し、**内部のルート算出ロジックにのみ使用する**。スケジュール表そのものの再配信・一覧表示は行わない。
- チケット予約は行わない。各映画館の公式ページへ誘導する。

## 2. スコープ

### 2.1 対象範囲（初期リリース = MVP）

| 項目 | 内容 |
|---|---|
| 対象エリア | 1都市圏から開始（初期: 大阪市内 + 周辺、劇場 5〜10館） |
| 対象日 | 当日 + 翌日〜7日先まで（取込データの範囲に依存） |
| 移動手段 | 公共交通（鉄道中心）+ 徒歩 |
| クライアント | Web（先行）。モバイルアプリは後続フェーズ |
| 利用者 | 未ログインで全機能利用可能（MVPでは認証なし） |

### 2.2 スコープ外（MVPでは作らない）

- チケット予約・座席選択・価格比較
- ユーザーアカウント / お気に入り / 履歴の永続化
- 上映スケジュールの一覧表示機能（法務方針により恒久的にスコープ外）
- リアルタイム運行情報（遅延）の反映
- 多言語対応

## 3. 機能要件

### 3.1 ルート算出（コア機能）

| ID | 要件 |
|---|---|
| F-01 | 利用者は対象日・スタート地点・ゴール地点・利用可能な時間帯（開始/終了時刻）を指定してルート算出を実行できる |
| F-02 | スタート/ゴール地点は「駅名」または「現在地（緯度経度）」で指定できる。ゴール地点は省略可（省略時は制約なし） |
| F-03 | 利用者は「マストで観たい映画」を0〜3本指定できる。マスト指定作品を含まないルートは提案しない |
| F-04 | 利用者は観たい映画の候補（ウィッシュリスト）を任意数指定できる。未指定の場合は上映中の全作品を候補とする |
| F-05 | システムは「鑑賞本数最大」のルートに加え、性質の異なる代替案を合計3〜5件提示する（代替案の定義は `05_routing-algorithm.md` §6） |
| F-06 | ルートには各上映の開始/終了時刻、劇場、劇場間の移動時間・経路概要、待ち時間を含める |
| F-07 | 各上映には該当劇場の公式ページ（可能なら該当作品のページ）へのリンクを付与する |
| F-08 | 到着マージン（上映開始の何分前に劇場に到着するか）は利用者が変更できる（デフォルト15分、範囲5〜60分） |
| F-09 | 実行可能なルートが存在しない場合、その旨と緩和候補（時間帯拡大・マスト解除等）を提示する |

### 3.2 共有・連携

| ID | 要件 |
|---|---|
| F-10 | 利用者はルートをGoogleカレンダーに登録できる。実装はカレンダーURLテンプレート方式（OAuth不使用）。上映1件 = 予定1件 |
| F-11 | 利用者はルートを .ics ファイルとしてダウンロードできる |
| F-12 | 利用者はルートを共有URLとして発行できる。共有ページはOGP画像を持ち、SNS共有（Web Share API / X / LINE）に対応する |
| F-13 | 共有URLは条件とルート内容のスナップショットを表示する（再計算しない）。有効期限は30日 |

### 3.3 取込サービス（内部）

| ID | 要件 |
|---|---|
| F-20 | 劇場ごとに日次で上映スケジュールを取得し、LLM抽出・検証を経てDBに保存する |
| F-21 | 取得した生HTMLはR2に保存し、再取得なしで再抽出できる |
| F-22 | 抽出結果がスキーマ検証・妥当性検証に失敗した場合、DBへ書き込まず管理者に通知する |
| F-23 | 劇場マスタで劇場の追加・無効化・取得方式の変更ができる |
| F-24 | 劇場マスタに規約確認メモ・確認日を記録できる。確認日が90日を超過した劇場は管理サイトで警告表示する |

### 3.4 管理サイト（内部）

| ID | 要件 |
|---|---|
| F-30 | 劇場マスタのCRUD |
| F-31 | 取込実行履歴の一覧・詳細表示（成功/失敗、件数、消費トークン、所要時間） |
| F-32 | 検証NGとなった抽出結果のレビューキュー（内容確認・手動承認・手動再実行） |
| F-33 | 劇場単位の手動取込トリガー |

## 4. `/plan` 入出力仕様（要点）

正式なスキーマは `04_api-spec.md` を正とする。ここでは意味的な仕様のみ定義する。

### 入力

```
date            : 対象日 (YYYY-MM-DD, JST)
timeWindow      : { start: "HH:mm", end: "HH:mm" }  # 利用可能時間帯
origin          : { type: "station"|"geo", value }   # スタート地点
destination     : origin と同型 | null                # ゴール地点（省略可）
mustMovieIds    : string[] (0..3)
wishMovieIds    : string[] (0..N, 空なら全作品)
arrivalMarginMin: number (5..60, default 15)
maxResults      : number (1..5, default 3)
```

### 出力

```
plans: [
  {
    label       : "最多鑑賞" | "移動少なめ" | "余裕あり" | ...
    stats       : { movieCount, totalTravelMin, totalWaitMin, endTime }
    legs: [
      { kind: "screening", theaterId, movieId, startAt, endAt, officialUrl },
      { kind: "travel", fromTheaterId, toTheaterId, departAt, arriveAt, summary },
      { kind: "wait", minutes }
    ]
  }
]
infeasible?: { reason, relaxSuggestions[] }  # ルートなしの場合
```

### 意味規則

- 上映レッグは重複しない。連続する上映の間には必ず travel（同一劇場なら省略可）+ 到着マージン分の余裕が存在する。
- `timeWindow.start` 以降に最初の上映（への移動出発）が始まり、最後の行動終了（destination指定時はゴール到着）が `timeWindow.end` を超えない。
- 同一作品を同一ルート内で2回観ることはない（IMAX/字幕違いも同一 movieId なら1回）。

## 5. 非機能要件

| ID | 項目 | 要件 |
|---|---|---|
| N-01 | レスポンス | `/plan` は p95 で 3秒以内（外部経路検索を呼ばないケースでは 1秒以内） |
| N-02 | データ鮮度 | 上映データは対象日の前日 06:00 JST までに取込完了していること |
| N-03 | 可用性 | 取込サービスの障害時も、公開サービスは最後に成功したデータで応答を継続する |
| N-04 | コスト | ランニングコスト月額 3,000円以内（LLM API・Cloudflare 有料枠含む） |
| N-05 | スケール上限（設計前提） | 劇場 30館 / 1日あたり上映 1,500件 / plan リクエスト 1,000件/日 まではアーキテクチャ変更なしで耐える |
| N-06 | 取得マナー | 同一サイトへのリクエスト間隔は最低5秒。1劇場の取得は原則**1日1セッション**（Cron 1回分の取込）で、1セッションのページ数は最大10（複数日取得を設定した劇場のみ。ADR-0019）。詳細はコンプライアンスポリシーに従う |
| N-07 | 監視 | 取込失敗・検証NG・LLMコスト急増は当日中に通知される |

## 6. 前提・制約（設計判断の背景）

1. **内部利用限定の原則**: 取得した上映スケジュールは、ルート算出の入力としてのみ使用する。UI上に表示するのは「算出されたルートに含まれる上映」のみであり、劇場・日付単位のスケジュール一覧は提供しない（経緯は ADR-0002）。
2. **予約導線は公式のみ**: 本サービスは予約機能を持たず、金銭も扱わない。
3. **劇場採用の条件**: robots.txt でクロール拒否されていない、かつ規約上問題がないと管理者が確認・記録した劇場のみ取込対象とする（F-24）。
4. **移動時間は事前計算**: 劇場間移動時間は週次バッチで行列として事前計算し KV に保持する。`/plan` 実行時の外部経路検索は origin/destination の解決に限る（経緯は ADR-0005）。
5. **認証なしMVP**: 個人情報を保持しない。共有URLもルート内容のみで、個人を特定する情報を含まない。
